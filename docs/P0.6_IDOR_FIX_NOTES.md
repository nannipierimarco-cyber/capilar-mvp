# P0.6 — IDOR fix: get-analysis access token

## Cambio en Supabase
**Ninguno.** El token de acceso es un HMAC-SHA256 stateless calculado en el servidor. No se requiere columna nueva ni migración SQL.

## Variable de entorno requerida

```
ANALYSIS_ACCESS_SECRET=<mínimo 32 caracteres aleatorios>
```

Agregar en Vercel (production + preview + development) antes de deployar:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
# copia el output y agrégalo con:
vercel env add ANALYSIS_ACCESS_SECRET production
vercel env add ANALYSIS_ACCESS_SECRET development
```

Para preview usa el dashboard de Vercel (CLI v53 requiere interacción para preview sin rama).

## Comportamiento si la variable no está configurada

- `GET /api/mapa-capilar/get-analysis` devuelve **503** — no expone datos.
- `POST /api/mapa-capilar/analyze` devuelve `accessToken: null` — el reporte sigue
  funcionando desde `sessionStorage` (el usuario ve el análisis pero sin fotos del servidor).

## Cómo probar manualmente

### Caso OK (usuario legítimo)
1. Ir a `/mapa-capilar`, subir fotos, hacer clic en "Generar mi mapa".
2. El reporte debe cargar con las fotos.
3. En DevTools → Application → Session Storage verificar que `mapa_capilar_access_token` existe.
4. En Network, el request a `/api/mapa-capilar/get-analysis` debe retornar 200 con `frontalUrl` y `crownUrl`.

### Caso IDOR bloqueado (acceso sin token)
```bash
curl "https://tu-dominio/api/mapa-capilar/get-analysis?id=<uuid-real>"
# Debe retornar: {"error":"Acceso no autorizado"} con status 403
```

### Caso token incorrecto
```bash
curl "https://tu-dominio/api/mapa-capilar/get-analysis?id=<uuid>&token=invalido"
# Debe retornar: {"error":"Acceso no autorizado"} con status 403
```
