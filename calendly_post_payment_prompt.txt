Implement Calendly scheduling layer for Nilo after successful payment.

Context:
Nilo already has:
- quiz
- Supabase
- AI doctor report
- admin
- doctor portal
- doctor_profiles
- medical_reviews
- Flow payment
- checkout/return
- success page

Now we need to connect Calendly in a scalable way for multiple doctors.

Business requirements:
1. After the user pays, they should be able to book a consultation with the assigned doctor.
2. Doctors will have their availability managed in Calendly.
3. Nilo should store enough Calendly metadata to know which doctor has which booking link/event type.
4. Nilo should eventually update the patient case when Calendly confirms a booking.

Important:
- Do not build a custom calendar availability system from scratch.
- Calendly should be the source of truth for doctor availability.
- Nilo should store Calendly links and event type identifiers.
- Do not break existing Flow payment.
- Do not break checkout.
- Do not break Supabase.
- Do not break doctor portal.
- Do not break admin.
- Do not break AI report.
- Do not expose Calendly API keys to the client.

Goal:
Create a post-payment scheduling page and prepare the foundation for Calendly availability/webhook sync.
