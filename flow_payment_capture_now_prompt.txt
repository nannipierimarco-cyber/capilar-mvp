Implement MVP payment integration using Flow Chile with immediate payment capture.

Important business requirement:
The customer must pay now.
This is NOT an authorization-only flow.
This is NOT “save card and charge later”.
This is “pay now, then medical review”.

Core flow:
1. User completes quiz.
2. User sees result.
3. User chooses Plan Inicio Capilar.
4. User pays now through Flow.
5. After successful payment, order status becomes:
   paid_pending_medical_review
6. Doctor reviews the case.
7. If doctor determines it corresponds to advance:
   treatment/farmacy/delivery process continues.
8. If doctor determines it does not correspond:
   doctor marks the case as not eligible / does not correspond.
   order status becomes refund_pending.
   operations team processes refund manually in Flow during MVP.

Core checkout copy:
“Reserva tu plan. El cargo queda sujeto a revisión médica. Si el médico determina que no corresponde avanzar, no activaremos el tratamiento y te devolveremos el pago.”

Compliance:
- Do not say prescription approved.
- Do not say treatment guaranteed.
- Do not say medication guaranteed.
- Do not say we sell medication directly.
- Say the doctor defines if treatment is clinically appropriate.
- Say medication is prepared/dispensed by authorized pharmacy when applicable.

Payment provider:
Use Flow Chile for MVP.
Use immediate captured payment.
Do not implement authorization-only.
Do not implement card tokenization yet.
Do not implement recurring charges yet.

Environment variables:
FLOW_API_KEY=
FLOW_SECRET_KEY=

NEXT_PUBLIC_APP_URL=

- save provider token/order data

3. Flow confirmation webhook

Create:
src/app/api/payments/flow/confirm/route.ts

It should:
- receive Flow confirmation
- verify payment with Flow API if required
- if payment is paid/successful:
  update order status to paid_pending_medical_review
  set paid_at
- if failed:
  update status to payment_failed
- store provider_status
- return valid response to Flow
